# Changelog

## 1.0.0 (2026-09-15)


### ⚠ BREAKING CHANGES

* **websearch:** TavilyWebSearch's constructor no longer takes an API key, and TavilySearchRequest no longer has an ApiKey property. Callers using AddTavilyWebSearch are unaffected.
* **abstractions:** let a native hybrid declare its fused score scale ([#530](https://github.com/MarcelRoozekrans/Rag.NET/issues/530)) (#531)
* **metadata:** throw on a corrupt metadata blob instead of reading it as empty ([#521](https://github.com/MarcelRoozekrans/Rag.NET/issues/521)) (#527)
* **redis:** store, return and filter on chunk metadata ([#513](https://github.com/MarcelRoozekrans/Rag.NET/issues/513)) (#522)
* **azureaisearch:** derive the document key, fixing duplicate writes and enabling keyed reads ([#518](https://github.com/MarcelRoozekrans/Rag.NET/issues/518))
* **core:** report a failed model call as ModelCallFailed, not StorageFailed ([#508](https://github.com/MarcelRoozekrans/Rag.NET/issues/508))
* **graphrag:** delete the PageRank-blend local search, keep its figures reproducible ([#408](https://github.com/MarcelRoozekrans/Rag.NET/issues/408))
* **dataproviders:** `ProviderIngestionResult.Ingested`, `.Skipped`, `.Failed` and `.Deleted` are now `IReadOnlyList<ProviderEntryOutcome>` instead of `int`. The counts are available unchanged as `IngestedCount`, `SkippedCount`, `FailedCount` and `DeletedCount`. Every call site fails to compile rather than changing meaning silently.
* **vectorstores:** IVectorStore declares InitializeAsync. It has a default no-op body, so existing external implementations keep compiling and behaving identically, and the five in-repo stores that already had the method matched its signature exactly.
* **di:** named pipelines — one container, several isolated RAG pipelines ([#342](https://github.com/MarcelRoozekrans/Rag.NET/issues/342)) (#381)
* **security:** split SQLite audit logging into its own package ([#339](https://github.com/MarcelRoozekrans/Rag.NET/issues/339)) (#376)
* **retrieval:** apply MetadataFilter to the BM25 arm of client-side hybrid ([#350](https://github.com/MarcelRoozekrans/Rag.NET/issues/350)) (#372)
* **raptor:** floor the cluster count on level size ([#345](https://github.com/MarcelRoozekrans/Rag.NET/issues/345)) (#351)
* **raptor:** RaptorRetrievalMode.Boost and RaptorRetrievalMode.Filter now issue their vector-store query at CandidateMultiplier x TopK (default 3x) instead of TopK. Retrieval cost for those two modes rises accordingly, and both can now return results they previously could not. Blend, the default, is unaffected. Set RaptorRetrievalOptions.CandidateMultiplier = 1.0 to restore the previous behaviour exactly.
* **raptor:** RaptorOptions.TreeScope defaults to Corpus instead of PerDocument. Corpus scope requires a leaf store: any existing UseRaptor(...) call that does not pass leafStorePath now throws ArgumentException at registration. Fix by either passing leafStorePath (and referencing Rag.NET.Raptor.Store) to adopt the new default, or by setting TreeScope = RaptorTreeScope.PerDocument explicitly to keep the previous behaviour unchanged.
* **graphrag:** finish Microsoft's local search — retire the blend, add conversation history ([#323](https://github.com/MarcelRoozekrans/Rag.NET/issues/323))
* **graphrag:** give the graph's chunks their own store ([#312](https://github.com/MarcelRoozekrans/Rag.NET/issues/312))
* **graph:** fold entity keys in .NET, and index the relationship lookups ([#304](https://github.com/MarcelRoozekrans/Rag.NET/issues/304))
* **graphrag:** debounce community detection, and add an explicit rebuild ([#302](https://github.com/MarcelRoozekrans/Rag.NET/issues/302))
* **graphrag:** default PageRankWeight to 0, which the measurement says costs nothing ([#296](https://github.com/MarcelRoozekrans/Rag.NET/issues/296))
* **graphrag:** GraphLocalSearchBehavior returns the candidates it previously discarded. Local search over a multi-document corpus now returns substantially more results -- three times as many over the measured slice -- and the ranking below the top changes, since chunks that were dropped now take their place by score. A caller that sized anything on the shortened list, or pinned retrieval output from UseGraphRag(), will see both move.
* **graphrag:** UseAuditLog and AddRagDiagnostics no longer register IAnswerEngine, and UseAuditLog no longer registers ChatAnswerEngine or AuditAnswerEngineDecorator by their concrete types. Resolving IAnswerEngine yields the registered engine, undecorated; resolve ComposedAnswerEngine for the engine the pipeline answers with. Compositions in which ConfigureResilience, UseCostBudgeting, UseRateLimiting or UseFallbackChain decorated nothing used to run with the feature quietly absent and now throw when the pipeline is resolved.
* **builder:** UseAuditLog and AddRagDiagnostics no longer register IAnswerEngine, and UseAuditLog no longer registers ChatAnswerEngine or AuditAnswerEngineDecorator by their concrete types. Resolving IAnswerEngine yields the registered engine, undecorated; resolve ComposedAnswerEngine for the engine the pipeline answers with. Compositions in which ConfigureResilience, UseCostBudgeting, UseRateLimiting or UseFallbackChain decorated nothing used to run with the feature quietly absent and now throw when the pipeline is resolved.
* **builder:** UseRaptor, UseGraphRag and UseMindMapExtraction place their behaviours ([#221](https://github.com/MarcelRoozekrans/Rag.NET/issues/221))
* **retrieval:** `RagBuilder.UseMmr()` is removed. Drop the call — `new RetrievalOptions { UseMmr = true }` is and always was what activates MMR.
* **graph:** community detection returns a different partition for a given seed. The refinement is randomised, so `RandomSeed` still fixes the result exactly, but a partition recorded against an earlier version will not reproduce.
* **graph:** `Rag.NET.Graph.Algorithms.Leiden` is renamed to `LouvainWithRefinement` and `LeidenOptions` to `LouvainWithRefinementOptions`; `Rag.NET.GraphRag.GraphRagOptions.Leiden` is renamed to `CommunityDetection`. The old names remain as `[Obsolete]` forwarders that delegate to the new ones, so existing code compiles with a deprecation warning rather than breaking.
* **quality:** MultiHop-RAG, and the six shipping defects that running it found ([#168](https://github.com/MarcelRoozekrans/Rag.NET/issues/168))
* **ci:** publish to nuget.org with Trusted Publishing instead of a stored key ([#148](https://github.com/MarcelRoozekrans/Rag.NET/issues/148))
* **options:** make every configure callback able to configure something ([#144](https://github.com/MarcelRoozekrans/Rag.NET/issues/144))
* **reranking:** stop the reranker silently deciding how many chunks an answer uses ([#145](https://github.com/MarcelRoozekrans/Rag.NET/issues/145))
* **gmail:** the query was never applied, and the options could not be set at all ([#141](https://github.com/MarcelRoozekrans/Rag.NET/issues/141))
* **mcp:** the HTTP transport served everything unauthenticated by default ([#131](https://github.com/MarcelRoozekrans/Rag.NET/issues/131))
* **graphrag:** delete Mode, a public setting nothing ever read ([#125](https://github.com/MarcelRoozekrans/Rag.NET/issues/125))
* **chunking:** fold TokenAware and Semantic into Rag.NET.Chunking
* **dataproviders:** merge the four Graph connectors into Rag.NET.DataProviders.Microsoft365
