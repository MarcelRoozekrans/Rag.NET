# HyDE (Hypothetical Document Embeddings) Design

**Date:** 2026-03-13

## Goal

Replace the query embedding with the embedding of a hypothetical "ideal answer document" generated by an LLM. Since hypothetical documents live in the same semantic space as indexed content (not the query space), they retrieve far more relevant passages — especially for short or ambiguous queries against long documents.

## Architecture

Same pattern as multi-query retrieval: public abstraction, internal LLM implementation, options class, `RagBuilder` method, per-call opt-out flag.

## Interfaces & Options

```csharp
public interface IHypotheticalDocumentGenerator
{
    /// <summary>
    /// Generates a hypothetical document that would ideally answer <paramref name="query"/>.
    /// The returned text is embedded and used for vector similarity search in place of the query.
    /// </summary>
    Task<string> GenerateAsync(string query, CancellationToken cancellationToken = default);
}

public sealed class HydeOptions
{
    /// <summary>
    /// Prompt template with a required <c>{query}</c> placeholder.
    /// The LLM response is used verbatim as the hypothetical document text.
    /// </summary>
    public string PromptTemplate { get; set; } =
        "Please write a short passage that directly answers the following question. " +
        "Write only the passage, no preamble or explanation.\n\n" +
        "Question: {query}";
}
```

## Data Flow

HyDE operates inside `SearchSingleQueryAsync`, so it composes automatically with multi-query fan-out (each variant gets its own hypothetical document):

```
RetrieveAsync(query)
  │
  ├─ [if multi-query] expand → [query, v1, v2, ...]
  │
  └─ per query string → SearchSingleQueryAsync(q, ..., useHyde)
        │
        ├─ [if HyDE active]
        │     textToEmbed = _hydeGenerator.GenerateAsync(q)   // LLM call
        │     (on failure: log warning, textToEmbed = q)
        │
        ├─ Embed(textToEmbed)                                  // embedding call
        │
        ├─ VectorStore.SearchAsync(embedding)                  // vector search
        │
        └─ [if hybrid] BM25.Search(q)  ← original query always used for keyword
```

Key invariant: the original `query` string is always used for BM25 and `IHybridSearchable.HybridSearchAsync` keyword arguments. Only the embedding vector is derived from the hypothetical document.

## Implementation Detail — `SearchSingleQueryAsync` change

```csharp
private async Task<IReadOnlyList<SearchResult>> SearchSingleQueryAsync(
    string query,
    SearchOptions searchOptions,
    bool useHybridSearch,
    bool useHyde,          // new parameter
    CancellationToken cancellationToken)
{
    var textToEmbed = query;

    if (useHyde && _hydeGenerator is not null)
    {
        try
        {
            textToEmbed = await _hydeGenerator.GenerateAsync(query, cancellationToken)
                .ConfigureAwait(false);
        }
        catch (OperationCanceledException) { throw; }
        catch (Exception ex)
        {
            RagPipelineLog.HydeGenerationFailed(_logger, query, ex);
            // textToEmbed remains = query (fallback)
        }
    }

    var queryEmbeddings = await embeddingGenerator.GenerateAsync(
        [textToEmbed], cancellationToken: cancellationToken).ConfigureAwait(false);

    // BM25 and HybridSearchAsync keyword arg always use original `query`
    ...
}
```

## DI Registration

```csharp
// Enable with defaults
services.AddRagNet(b => b.UseHyde());

// Custom prompt
services.AddRagNet(b => b.UseHyde(o =>
    o.PromptTemplate = "Write a document answering: {query}"));

// Per-call opt-out
var results = await pipeline.RetrieveAsync("query", new RetrievalOptions { UseHyde = false });
```

## Error Handling

- `OperationCanceledException`: re-thrown immediately (cooperative cancellation).
- All other exceptions: caught, `HydeGenerationFailed` logged at `Warning` level, falls back to original query embedding. No exception propagates to the caller.
